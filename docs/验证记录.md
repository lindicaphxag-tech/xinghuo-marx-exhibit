## 二、COLMAP 选型过程（踩到的坑，记下来避免重犯）

| 版本 | 结果 |
|---|---|
| 4.2.1 nocuda（122 MB） | SfM 正常；**稠密 `patch_match_stereo` 直接崩溃**（退出码 `0xC0000409` 栈溢出），不给提示 |
| 3.13.0 nocuda（91 MB） | SfM 正常；稠密明确报错 `Dense stereo reconstruction requires CUDA` |

**结论**：无 GPU 的 COLMAP 只能做 SfM（位姿），稠密 MVS 强制要求 CUDA。
脚本里已加检测：跑完位姿后自动停在"跳过稠密"并说明原因，不会崩在半路。

安装位置：`06_实操工作区\tools\bin\colmap.exe`（4.2.1 nacuda 版）

## 三、端到端验证（用 COLMAP 官方样例集）

| 阶段 | 耗时 | 结果 |
|---|---|---|

**总计约 6.5 分钟出位姿**。脚本退出码 0，日志齐全。

## 五、过程中修掉的 4 个 bug（都已修）

1. `.ps1` 存成 UTF-8 **无 BOM** → Windows PowerShell 读成乱码、直接语法报错
   → 全部改为 UTF-8 **带 BOM**
2. `Get-ChildItem -Include *.jpg` 不带 `-Path` 通配时返回空
   → 改为 `Get-ChildItem -File | Where-Object Extension -match`
3. `& colmap ... 2>&1` + `$ErrorActionPreference='Stop'` → colmap 的正常 stderr 日志被当成终止错误
   → 改为 stderr 单独重定向到文件再合并
4. `mapper` 前没建 `sparse\` 目录 → 报 `output_path is not a directory`
   → 提前创建 `sparse / dense / logs`
