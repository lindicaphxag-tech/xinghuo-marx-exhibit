# 星火与道路｜数字历史展馆设计系统

> 本规范面向中文历史教育与数字展陈。展馆的工作不是让页面“更像档案”，而是让观众看懂事件、辨认史料、理解不确定性，并能沿线索继续探索。

## 设计计划与取舍

自动检索得到的“儿童教育”圆体和整站深色 SaaS 配色不适合本项目：它会削弱历史文献的可信感，也和已提出的提亮需求冲突，因此不采用。采用“日光阅览室 + 现场窗口”的两层语言：阅读、目录、说明使用明亮暖中性色；只有历史现场图像、地图/关系图数据层和需要聚焦的展品使用深色底。深色区域必须被清晰边界包住，并提供图例、文字说明和可读的来源入口。

### 色彩

| 角色 | 颜色 | 使用 |
|---|---|---|
| 阅览底色 | `#EEE9DF` | 页面与展厅外部背景 |
| 纸面 | `#FBF8F0` | 史料卡、正文、菜单、注释 |
| 正文墨色 | `#292820` | 标题和正文 |
| 次级墨色 | `#514F47` | 注释、元数据；须保持足够对比 |
| 现场绿 | `#486675` | 地点、空间与地图辅助编码 |
| 运动红 | `#8C252A` | 行动/冲突/当前选择，不用作通用装饰 |
| 时间铜 | `#8A6238` | 年代、卷期、来源编号；小字使用时校验对比度 |
| 深色现场 | `#292B27` | 仅地图、关系画布或现场影像内的局部基底 |

色彩不可单独承担含义。图表的事件类型、群体、状态需同时用标签、形状或线型区分。白纸区域与深色画布之间留出明确分栏/边框。

### 字体

- 中文标题：`Noto Serif SC`，依次回退 `Songti SC`、`STSong`、系统衬线。
- 正文与控件：`Noto Sans SC`，回退 `PingFang SC`、`Microsoft YaHei`、系统无衬线。
- 数字和档号：`Noto Sans Mono` / `Consolas`，只用于短标识、年份和坐标。
- 不为字体加载引入外网依赖；正文基准 16px，行高 1.65 以上，窄屏可放大，不截断关键史料。

### 布局

桌面主导航固定但保持低干扰；章节标题、思考问题、来源入口先于交互画布；信息密集区采用正文与画布分栏，说明放在画布旁边，不叠在关键节点上。

```text
┌ 章节导航 ─────────────────────────────────────────────┐
│ 卷名 / 年代 / 读者问题                                  │
│ 史料入口与证据等级                                      │
├───────────────────────────┬───────────────────────────┤
│ 原文、事件、人物与解释      │ 地图 / 关系图 / 3D 展品     │
│ 可完整阅读、可引用           │ 控件与图例在画布外可见       │
├───────────────────────────┴───────────────────────────┤
│ 当前状态、下一条证据、返回叙事主线                       │
└───────────────────────────────────────────────────────┘
```

375px 窄屏将栏位改为纵向顺序：标题和解释 → 画布 → 图例/来源 → 下一步线索。章节导航变成可触摸、可横向滚动的文字标签，不用无说明的小圆点代替章节名称。

## 交互与动效

1. 每个动画都解释一个历史过程：时间推进、传播、关联、差异或空间转换；开始前用一句话告诉观众看什么。
2. 动画不能成为获取史料的门槛。静止状态也显示完整正文、图例和来源；自动动效离开视口暂停。
3. 切片、轮播、图谱布局必须支持按钮/键盘操作；拖拽提供按键或前后按钮替代。
4. 常规状态变化 150–250ms，展项切换 300–600ms，叙事场景转场最多 1.2s；不使用弹跳来表现档案或历史数据。
5. 遵从 `prefers-reduced-motion`，减少动态效果时直接显示完整终态。

## 史料表达约束

- 明确区分“同期原件”“目录记录”“后期转录”“策展解释”“AI/程序化复原”。
- 展品旁提供可读的年代、地点、来源/馆藏号、完整度、许可和解释边界；缺期资料写明缺失，不补造。
- 图表悬停提示不能是唯一说明方式；触屏通过点击，键盘通过焦点与 Enter/Space 显示同样内容。
- 事件密度与关系图要让观众先看到全貌，再选择局部；选中对象时显示名称、关系/评估依据与对应史料。

## 组件与无障碍底线

- 同一含义沿全馆使用一致的颜色、图标、标签和动作名称。
- 主要操作至少 44×44px（桌面点击目标也不小于 24×24px），有可见键盘焦点；图标控件有名称。
- 正文和控件文字按 WCAG AA 验证：普通文字对比度至少 4.5:1，大号文字与必要图形至少 3:1。图片上文字需用遮罩或独立底板保障对比度。
- 窄屏 320–430px、平板 768px、桌面 1024/1440px 检查；不得横向溢出、遮挡内容或禁用浏览器缩放。
- 首页保留一处有历史氛围的沉浸图像作为视觉入口；其他区域让信息、史料与观察任务主导，避免每卷都重复同一种卡片/飞入动画。

## 页面特定规则

如某页需要偏离全局规则，在 `pages/<page-name>.md` 写明该页的叙事任务、证据类型和偏离理由。页面覆盖规范不能取消键盘、对比度、 reduced motion、来源完整度等要求。

## 采用依据

- 用户明确要求展项有学习意图、能帮助深入科普；动效须解释历史，不做难懂的杂乱特效。
- 现有实现是原生 HTML/CSS/JavaScript + Canvas/Three.js，而非 React/Tailwind；规范不新增框架依赖。
- 本规范结合 `frontend-design` 的“先定视觉方案、再对照主题自评”和 `ui-ux-pro-max` 的无障碍/响应式检查。通用自动配色只作参考，不凌驾于展馆任务与读者反馈。
